STEP 3D.1 — A POLISHED INVITE SHARE CARD

The goal is to replace the ugly/raw visible invite URL experience with a small, premium share-card experience that feels native to “us”.

==================================================
PRODUCT INTENT
==================================================

When an existing user taps:

invite friends

they should NOT primarily see/copy something like:

http://192.168.1.4:3001/invite/2ecc788fa907495c02dc85a5b861e56a

The opaque URL remains the actual attribution mechanism underneath.

But the user-facing sharing experience should communicate:

“join us”
“i'm #42”
“secure your spot”

where #42 is the user's real permanent #spot.

The card should feel like something a student would actually send to a friend.

It should NOT look like:
- a generic SaaS share dialog
- a QR-code poster
- a marketing banner
- a coupon
- a corporate referral card
- a crypto invite
- an Instagram clone

Keep it minimal, editorial, romantic, youthful, and premium.

==================================================
IMPORTANT COPY
==================================================

Use the user's actual spot dynamically.

Primary concept:

join us.

i'm #42.

secure your spot.

Where:

#42

is dynamically replaced with the current user's permanent #spot.

Also include the user's public username where appropriate:

@username

Do NOT expose:
- USN
- email
- auth user ID
- invite token
- internal database ID

Do not invent additional claims such as:
- “only 100 spots”
- “exclusive”
- “limited”
- “your friends are waiting”
- “first 100 users”
unless already explicitly supported by the product specification.

The permanent #spot is the only scarcity/identity concept we should use.

==================================================
6. NATIVE WEB SHARE
==================================================

Use the native Web Share API where supported.

Prefer sharing the generated card image/file if the browser supports:

navigator.share({
  files: [...]
})

The shared content should also contain useful fallback text:

title:
"join us."

text:
"i'm #<spot>. secure your spot."

url:
absolute invite URL

Do not rely exclusively on file sharing because browser support varies.

Feature-detect:

navigator.share
navigator.canShare
navigator.canShare({ files })

Do not throw when unsupported.

==================================================
7. CARD IMAGE GENERATION
==================================================

We need an actual image for native file sharing.

Choose the smallest dependency-free approach compatible with the project.

Prefer NOT adding a heavy image/canvas library.

If a browser-native Canvas implementation is sufficient, use it.

The generated card should match the visual React preview closely.

Important:

- devicePixelRatio-aware rendering
- deterministic dimensions
- readable typography
- no blurry text
- no huge image file
- no external network dependency
- no remote font dependency
- no personal data beyond username/#spot
- no invite token rendered into the image

Use a sensible share-card aspect ratio.

Prefer a portrait social-share format suitable for messaging apps.

Do not optimize for Instagram specifically.

==================================================
8. IMPORTANT: DO NOT BREAK EXISTING FALLBACKS
==================================================

Current implementation already handles insecure LAN development where:

navigator.share
and
navigator.clipboard

may be unavailable.

Preserve this behavior.

Fallback order should be approximately:

1. native file share if supported
2. native URL/text share if supported
3. Clipboard API
4. legacy textarea + execCommand fallback
5. visible readonly link field for manual copying

Do NOT regress LAN development.

The absolute URL fix must remain.

Use:

new URL(inviteUrl, window.location.href)

or equivalent.

Never share:

/invite/<token>

as the final standalone URL if it can become relative outside the app.
