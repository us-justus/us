6. MESSAGE HISTORY
==================================================

Create:

src/lib/chat/queries.ts

Use a server-side query.

Fetch only:

- id
- sender_id
- body
- created_at

Query:

WHERE match_id = current match

ORDER BY created_at DESC

LIMIT 50

Then reverse the result for chronological rendering.

Do NOT use SELECT *.

Do NOT fetch unbounded history.

The composite index:

(match_id, created_at)

must support this query.

No pagination UI in this MVP.

Structure the query so keyset pagination can be added later without rewriting the data model.

7. SEND MESSAGE
==================================================

Create:

src/lib/chat/actions.ts

Implement:

sendMessageAction(matchId, body)

Use a Server Action.

Server responsibilities:

1. authenticate user
2. verify product/launch access as appropriate
3. validate matchId
4. explicitly verify current user belongs to match
5. trim body
6. reject whitespace-only messages
7. reject body > 1000 characters
8. set sender_id = authenticated user ID
9. insert message
10. return a typed result

The client MUST NOT supply sender_id.

The client MUST NOT be trusted for match membership.

Use a generic failure message such as:

"couldn't send — try again"

Do not expose PostgREST/database errors.

Do not use dangerouslySetInnerHTML.

Do not add a new API route.

10. OPTIMISTIC SEND
==================================================
